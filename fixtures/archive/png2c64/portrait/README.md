## png2c64 `--sharpen` renders (#228)

`baseline_sharpen_0.5.png` and `baseline_sharpen_-0.5.png` are png2c64's previews of `source.png` with the baseline's command below plus `--sharpen 0.5` or `--sharpen -0.5`, from the reference build (`docs/reference/png2c64-reference.md`: commit `1265329a`, GCC 15, `-ffp-contract=off`). `convert64 convert source.png` with the same settings and `--sharpen ±0.5` must reproduce them on ≥ 99.9 % of pixels (`crates/convert64-cli/tests/png2c64_convert.rs`, removed in #261 when png2c64 stopped being the gate).

## png2c64 baseline

Generated by `cargo xtask png2c64-baselines`; do not edit this section by hand.

- Tool: png2c64 1.0.0.76, commit `1265329a573b1dfa3c2e0f3473d2aa15ffd7ac3f` (<https://github.com/tinic/png2c64>)
- Mode: multicolor bitmap (Koala)
- Command, run in a directory holding a copy of `source.png`:

  ```sh
  png2c64 --mode multicolor --palette pepto --dither checker --dither-strength 0.7 --error-clamp 0.1 --gamma 1.5 source.png baseline.png
  ```

- Files: `baseline.png` is png2c64's 320×200 preview; `baseline.kla` is the picture data from the display PRG png2c64 writes, with the format's load address in front (see [fixtures/README.md](../../../README.md#png2c64-baselines-archived)).
- png2c64 total error (sum of per-cell OKLab errors, two decimals): 543.44
- `convert64 validate baseline.kla`: `legal` (exit 0)
